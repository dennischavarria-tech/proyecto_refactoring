5. RIESGOS DETECTADOS
================================================================================

  1. COBERTURA DE exceptions/not_found.py (56%)
     Severidad: BAJA
     Las clases MovieNotFoundError y SeriesNotFoundError estan definidas pero
     no se lanzan en el flujo actual. Cuando se implemente la logica de
     "no encontrado", deberan agregarse tests especificos.

  2. UI NO TESTEADA
     Severidad: MEDIA
     Los componentes de UI (menu.py, display.py) no tienen tests. Cualquier
     cambio en la logica de navegacion del menu podria introducir bugs sin
     ser detectados. Se recomienda refactorizar para separar logica de
     presentacion.

  3. MANAGERS NO TESTEADOS
     Severidad: MEDIA
     Hay 20+ modulos manager que no tienen cobertura de tests. Estos modulos
     manejan datos persistentes y logica de negocio importante. Se recomienda
     crear tests de forma incremental priorizando los de mayor riesgo.

  4. DEPENDENCIA DE VARIABLES DE ENTORNO
     Severidad: BAJA
     Los tests dependen del fixture mock_env_vars para configurar variables
     de entorno. Si constants.py se importa antes del fixture, los valores
     pueden no ser los esperados. Mitigado con asignacion directa de
     _api_key en el fixture mock_omdb_client.

  5. DATOS LOCALES EN CONSTANTS
     Severidad: BAJA
     POPULAR_MOVIES y GENRE_MOVIES estan hardcodeados en constants.py. Los
     tests que dependen de estos datos podrian fallar si se modifican.
     Se recomienda parametrizar estos datos o moverlos a archivos de
     configuracion.
